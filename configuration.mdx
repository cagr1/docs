OrchestOS has three configuration layers:

- **`orchestos.config.yaml`** at the project root — role assignments and harness options. Most of it is editable from **Settings** in the dashboard.
- **`~/.orchestos/.env`** — optional API keys, global to your machine.
- **`CONSTITUTION.md`** at the project root — optional rules injected into every task prompt.

## Roles

Four roles decide which agent and model handle each kind of call:

```yaml
config_version: 1
roles:
  orchestrator: { agent: claude, model: claude-opus-5-5, effort: medium }  # chat + task drafts
  executor:     { agent: codex,  model: gpt-6-luna,      effort: medium }  # writes the files
  reviewer:     { agent: codex,  model: gpt-6-luna,      effort: medium }  # QA verdict
  auxiliary:    { agent: codex,  model: gpt-5.6-luna }                     # diagnosis, memory judge
```

`agent` is `claude`, `codex`, `opencode`, or `api`. Edit roles in **Settings → Model routing**, or by hand in the file. Nothing is hardcoded: each role uses exactly what is configured, and a missing role stops with an error asking you to assign it. Full details in [Model routing](/reference/models).

## Other fields

```yaml
requireSpec: false        # true = every task needs an approved spec before running
apiMode: single-shot      # only for agent: api — single-shot | agentic
agentic:
  maxIterations: 15       # tool-use rounds per attempt when apiMode is agentic
external:
  timeoutMs: 1200000      # wall-clock limit for one CLI call (default 20 min)
adversarialQA: false      # opt-in second judge after a QA pass
refuterQA: false          # opt-in re-check after a QA fail, before spending a retry
```

See the [config file reference](/reference/config) for every field, including per-task agent rules.

## ~/.orchestos/.env

API keys are optional. You need none if every role uses a CLI agent. OrchestOS loads this file at startup for every command.

```bash
# ~/.orchestos/.env
OPENROUTER_API_KEY=sk-or-...    # roles with agent: api (default provider)
ANTHROPIC_API_KEY=sk-ant-...    # direct Anthropic calls
OPENAI_API_KEY=sk-...           # embeddings (text-embedding-3-small)
```

<ParamField path="OPENROUTER_API_KEY" type="string">
  Used by roles with `agent: api` when `provider` is omitted or set to `openrouter`. Get one at [openrouter.ai](https://openrouter.ai).
</ParamField>

<ParamField path="ANTHROPIC_API_KEY" type="string">
  Used by roles or tasks that call the Anthropic API directly. Get one at [console.anthropic.com](https://console.anthropic.com).
</ParamField>

<ParamField path="OPENAI_API_KEY" type="string">
  Used for `text-embedding-3-small` embeddings during `orchestos index`. When present, context suggestions are re-ranked by semantic similarity plus keyword matching. The effect is visible as `embed_hits` in `orchestos runs --detail`.
</ParamField>

<Note>
  `.env` holds secrets. It lives in your home directory to stay outside every project repository. Do not commit it.
</Note>

## CONSTITUTION.md

`CONSTITUTION.md` is an optional file at your project root. OrchestOS injects its contents into every task prompt — no config needed.

```bash
orchestos constitution init ./my-project   # scaffold CONSTITUTION.md
orchestos constitution show ./my-project   # print parsed rules
```

### Format

```markdown
# CONSTITUTION.md

## ALLOWED
- Modify files under src/

## FORBIDDEN
- Modify .env files
- Delete files

## REQUIRE_CONFIRMATION
- Any change to src/db/schema.ts
```

<ParamField path="## ALLOWED" type="section">
  Actions or paths the agent is explicitly permitted to touch.
</ParamField>

<ParamField path="## FORBIDDEN" type="section">
  Actions or paths the agent must never touch. The agent sees these in its prompt and is instructed to refuse.
</ParamField>

<ParamField path="## REQUIRE_CONFIRMATION" type="section">
  Files or actions that need a human checkpoint even when the task's contract permits the write.
</ParamField>

<Note>
  The constitution is an instruction in the prompt. The hard boundary is the `output[]` contract, which OrchestOS enforces after the executor runs. See [Contracts](/concepts/contracts).
</Note>
