Configure project behavior in `orchestos.config.yaml`. You can use `~/.orchestos/config.yaml` as a fallback. The first readable configuration file wins; project settings do not merge with the global file. Global `clis` declarations are loaded separately.

## Assign roles

Open **Settings → Model routing** to choose an agent and model for each role:

| Role | Used for |
| --- | --- |
| Orchestrator | Chat and task drafting. |
| Executor | Task execution. |
| Reviewer | Review criteria and applicable review gates. |
| Auxiliary | Diagnosis, pattern analysis, and memory conflict judging. |

Role agents are `claude`, `codex`, `opencode`, `api`, and custom IDs from global `clis`. A missing assignment stops the call that needs it. See [Model routing](/reference/models).

Inside **Model routing**, use the **Task rules** row to route drafted tasks by output glob or skill. Use **Executor** settings for API mode and execution limits.

```bash
orchestos config init ./my-project
orchestos config show -p ./my-project
```

`config init` writes a legacy model scaffold; assign any missing roles before running tasks. See the [config file reference](/reference/config) for its exact contents and ranges.

## Permissions

Set `permissionMode: manual` to hold all chat-created tasks for approval. With the default `yolo`, tasks that touch existing files still wait for approval; tasks that only create files can start directly.

The composer's **Supervised**, **Auto-edit**, and **Full access** selector controls action approvals within a task. It is separate from approval to start the task. See [Dashboard](/guides/dashboard#approvals).

## API keys

You need no API key for calls handled by a signed-in CLI. API calls use the corresponding provider key:

```bash
# ~/.orchestos/.env
OPENROUTER_API_KEY=
ANTHROPIC_API_KEY=
OPENAI_API_KEY=
```

| Key | Provider |
| --- | --- |
| `OPENROUTER_API_KEY` | `openrouter`, the default API provider. |
| `ANTHROPIC_API_KEY` | `anthropic`. |
| `OPENAI_API_KEY` | `openai`. |

You can manage keys under **Settings → API keys**. Keep the file outside your project repository.

## Environment variables

| Variable | Purpose |
| --- | --- |
| `ORCHESTOS_HOME` | Overrides the home root. State lives under `<ORCHESTOS_HOME>/.orchestos`, not directly in the supplied directory. |
| `ORCHESTOS_DASHBOARD_TOKEN` | Overrides the persisted dashboard token. |
| `OS_ENABLE_EXEC_CODEX` | Set to `1` to accept legacy `executor: codex` in tasks. It is separate from `engine: codex`. |
| `ORCHESTOS_API_URL` | Dashboard base URL for `skill curate`, `skill import`, and `skill fetch`; default `http://localhost:4242`. |
| `OLLAMA_HOST` | Local-model host setting stored by the dashboard. Current local chat and model probes use `http://localhost:11434` directly; changing this setting does not redirect those calls. |

## Stored files

| Path | Contents |
| --- | --- |
| `~/.orchestos/config.yaml` | Global fallback config and trusted custom CLI declarations. |
| `~/.orchestos/.env` | Optional API credentials and settings. |
| `~/.orchestos/db.sqlite` | Projects, runs, memory, and instincts. |
| `~/.orchestos/dashboard-token` | Generated dashboard authentication token. |
| `~/.orchestos/profile.json` | Whether you write code. The noncoding profile requires review. |
| `~/.orchestos/skills/` | Your reusable skill library. |
| `.orchestos/skills.json` | Skill-library activation for the project. |
| `.orchestos/specs/` | Project specs. |

All home paths above use `ORCHESTOS_HOME` when set. See [Skills](/guides/skills) and [Specs](/guides/specs).
