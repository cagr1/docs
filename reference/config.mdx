`orchestos.config.yaml` lives at the root of your project. It holds the role assignments and harness options. Most fields are editable from **Settings** in the dashboard; the file is the source of truth either way. If the file is absent, built-in defaults apply — but roles have no default, so assign them before running tasks.

## Initializing and inspecting config

```bash
orchestos config init ./my-project   # scaffold orchestos.config.yaml (fails if it exists)
orchestos config show ./my-project   # resolved config + which model each pending task would use
```

## Full example

```yaml
config_version: 1

roles:
  orchestrator: { agent: claude, model: claude-opus-5-5, effort: medium }
  executor:     { agent: codex,  model: gpt-6-luna,      effort: medium }
  reviewer:     { agent: codex,  model: gpt-6-luna,      effort: medium }
  auxiliary:    { agent: codex,  model: gpt-5.6-luna }

taskAgentRules:
  - match: { output: ["apps/api/**"] }
    agent: codex
    model: gpt-6-luna

requireSpec: false
apiMode: single-shot
agentic:
  maxIterations: 15
external:
  timeoutMs: 1200000
adversarialQA: false
refuterQA: false
```

## Fields

<ParamField path="config_version" type="integer" required>
  Schema version. Always `1`.
</ParamField>

<ParamField path="roles" type="object">
  Assignments for `orchestrator`, `executor`, `reviewer`, and `auxiliary`. Each is `{ agent, model, effort?, provider? }` with `agent` one of `claude`, `codex`, `opencode`, `api`. An invalid entry is ignored with a warning, never silently replaced. See [Model routing](/reference/models).
</ParamField>

<ParamField path="taskAgentRules" type="array">
  Declarative rules that send matching tasks to a specific agent and model. Each rule has `match` (`output` globs and/or `skill` id), `agent`, and optional `model` and `cli_effort`. Applied when a task is drafted. Editable in **Settings → Task rules**. See [Task rules](/reference/models#task-rules).
</ParamField>

<ParamField path="requireSpec" type="boolean" default="false">
  When `true`, every task must have an approved spec in `.orchestos/specs/<task-id>.md` before it can run. See [Specs](/guides/specs).
</ParamField>

<ParamField path="apiMode" type="string" default="single-shot">
  Only applies when the executor uses `agent: api`. A CLI agent decides this itself.

  - `single-shot` — one prompt, one parsed response.
  - `agentic` — a multi-turn tool-use loop, capped by `agentic.maxIterations`.
</ParamField>

<ParamField path="agentic.maxIterations" type="integer" default="15">
  Maximum tool-use rounds within one attempt when `apiMode` is `agentic`. This is separate from QA retries, which are fixed at three before a task becomes `failed_permanent`.
</ParamField>

<ParamField path="external.timeoutMs" type="integer" default="1200000">
  Wall-clock limit for one CLI agent call, in milliseconds (default 20 minutes). It guarantees the run ends; it is not a cost cap.
</ParamField>

<ParamField path="adversarialQA" type="boolean" default="false">
  Opt-in. After the reviewer passes a task, a second adversarial judge checks it before the merge. Doubles the QA calls for every task that passes.
</ParamField>

<ParamField path="refuterQA" type="boolean" default="false">
  Opt-in. After the reviewer fails a task, a cheap re-check looks for a false negative before a retry is spent. Adds one QA call to every failure.
</ParamField>

## Legacy fields

These are still parsed so older configs keep working:

- **`models.planner / executor_heavy / qa`** — migrated to `orchestrator`, `executor`, and `reviewer` when the role is not set. See [Migrating from the legacy models block](/reference/models#migrating-from-the-legacy-models-block).
- **`models.executor_light / default`** — parsed, no role equivalent.
- **`agent`** (top level) — the old project-wide agent preference. `executorEngine` and `executor_mode` values are translated to it (`external` → `claude`). The Executor role now decides the agent.
