Run commands from your project directory unless you supply a path. Optional `[path]` arguments default to the current directory.

## Project detection and context

| Command | Behavior and options |
| --- | --- |
| `detect [path]` | Detect the stack and write `AGENTS.md` and `context.json`, without saving a project record. `--force` permits replacing an existing `AGENTS.md`. |
| `init [path]` | Detect, write those files, and save the project in SQLite. `--pdf` adds a summary PDF. `--force` permits replacing `AGENTS.md`. |
| `summary [path]` | Generate a summary PDF. `--out <file>` selects its path. |
| `context show [path]` | Print the saved project context. |
| `context update [path]` | Re-detect and update context on disk and in SQLite. `--force` permits replacing `AGENTS.md`. |
| `context list` | List saved projects. |
| `context compress [path]` | Generate `CONTEXT.md` from saved context and print token estimates. |
| `roadmap show [path]` | Print the cached `docs/roadmaps/project-profile.md`. |
| `roadmap check [path]` | Detect applicable disciplines, languages, and infrastructure, then regenerate the profile. |

`detect`, `init`, and `context update` refuse to overwrite an existing `AGENTS.md` without `--force`. Read any manual rules before intentionally replacing them.

## Task commands

```bash
orchestos task init ./my-project
orchestos task list ./my-project
orchestos task status ./my-project
orchestos task run ./my-project --explain add-health
orchestos task run ./my-project --id add-health
orchestos task run ./my-project --all
```

`task init` scaffolds two starter tasks and refuses to overwrite `tasks.yaml`. Edit them before execution. `list` shows status and dependencies; `status` includes retries, QA, and accumulated cost.

### Task run options

| Option | Behavior |
| --- | --- |
| `--id <task-id>` | Run one task. Exit status is `1` unless the result is `done`. |
| `--all` | Run ready pending tasks, up to 20 iterations. Stop on failure or blockage. |
| `--explain <task-id>` | Print task metadata, resolved model and executor, inputs, checks, and criteria without executing a task or calling an LLM. |
| `--clarify <task-id>` | Ask for clarification before executing the task. |
| `--sandbox <mode>` | `auto` (default), `worktree`, or `cwd`. |
| `--keep-worktree` | Keep the worktree on failure; implies worktree mode. |
| `--project-id <project-id>` | Store run evidence under this registered project ID. Otherwise use `ORCHESTOS_PROJECT_ID` or the project registered for the path. |
| `--model <model>` | Transient model override. |
| `--engine <engine>` | Transient engine override. |

Valid engine IDs are `single-shot`, `agentic`, `external` (Claude Code), `opencode`, `codex`, and `cli:<id>` for each globally configured custom CLI. Model and engine flags do not persist their overrides in `tasks.yaml`.

In `auto`, a dirty git tree leaves the task `pending` with `retry_reason: "uncommitted changes: ..."`. It does not consume an attempt. Without git, or with a clean detached HEAD and no usable base branch, execution falls back to `cwd`. See [Sandbox](/concepts/sandbox).

`--all` does not keep running past a failed or blocked result. When no pending task is executable, it reports the blocked tasks and exits with an error.

### Diagnose

```bash
orchestos task diagnose add-health
orchestos task diagnose add-health --model <model>
```

Diagnosis reads up to three recent runs for the task and project. It uses the Auxiliary role unless `--model` selects an API model through OpenRouter. It suggests a fix without editing `tasks.yaml`.

Patterns are `deterministic_check`, `qa_specific_criterion`, `parse_error`, `rate_limit`, `scope_creep`, and `unknown`. `rate_limit` covers provider rate limits, HTTP 429, or token quota errors. When recorded failure evidence already identifies the cause, diagnosis can use that evidence directly.

## Ad hoc runs

```bash
orchestos run --task "Add a health endpoint" --output src/routes/health.ts
orchestos run --graph
```

| Option | Behavior |
| --- | --- |
| `--task <description>` | Required unless `--graph` is set. |
| `--output <paths>` | Comma-separated allowed output files; required unless `--graph` is set. |
| `--file <paths>` | Comma-separated input files. |
| `--skill <id>` | Primary skill. |
| `--project <path>` | Project root. |
| `--dry-run` | Print the ad hoc prompt, or the dependency plan with `--graph`, without executing. |
| `--graph` | Run the workflow declared in `tasks.yaml`. |
| `--max-cost <usd>` | Cost circuit breaker for `--graph`. |
| `--max-minutes <n>` | Wall-clock circuit breaker for `--graph`. |
| `--sandbox <mode>` | `auto` (default), `worktree`, or `cwd`. |
| `--keep-worktree` | Retain a failed worktree; implies worktree mode. |

## Run evidence

```bash
orchestos runs
orchestos runs --limit 20
orchestos runs --detail <run-id>
orchestos runs --export
orchestos runs --analyze --last 20
```

`--limit` defaults to `10`. `--detail` shows evidence for one run. `--export` writes `runs-export.json` in the current directory. Analysis uses the current project's runs, or unscoped runs when no project is registered. It requires at least three runs. Patterns with frequency at least `3` can produce unverified instinct proposals.

## Configuration

```bash
orchestos config init ./my-project
orchestos config show ./my-project
orchestos config show -p ./my-project
```

`config show` also accepts `--project <path>` and shows routing for pending tasks. `config init` writes the legacy model scaffold and refuses to overwrite an existing file. See [Config file](/reference/config).

## Skills

| Command | Options and behavior |
| --- | --- |
| `skill add <id>` | Scaffold `skills/<id>.yaml`. |
| `skill list` | List available skills and targets. |
| `skill build` | Export compiled instructions to `dist/skills/<target>/`. `--target <claude\|cursor\|openai>`, `--id <id>`, `--project <path>` for language-aware compilation. |
| `skill scaffold` | Required `--language <lang>`. Optional `--id <id>`, `--out <path>`. Default ID is `<language>-development`; default path is `skills/<id>.yaml`. |
| `skill languages` | Print supported language names. |
| `skill curate <description>` | Generate YAML through the dashboard curator. `--save` saves the result through the dashboard. |
| `skill import <url>` | Fetch, normalize, and save a skill through the dashboard. |
| `skill fetch --list` | List community-registry skills through the dashboard. |
| `skill fetch --name <id>` | Import one registry skill through the dashboard. |

Curate, import, and fetch require the dashboard at `ORCHESTOS_API_URL` or `http://localhost:4242`. Runtime loads YAML rather than exported instructions. See [Skills](/guides/skills).

## Instincts

```bash
orchestos instinct list --unverified
orchestos instinct list --source manual
orchestos instinct add --trigger "Billing convention" --action "Use the shared Stripe client"
orchestos instinct propose --trigger "Repeated failure" --action "Check the shared client"
orchestos instinct review
orchestos instinct approve <id>
orchestos instinct reject <id>
orchestos instinct set-confidence <id> 0.9
```

`instinct add` requires `--trigger` and `--action`; `--confidence` overrides `1.0`. Manual additions are verified, but the current `instinct add` command does not attach a project ID, so its entries are not injected by the project-scoped runtime. Proposals start unverified at `0.6`. Approval sets confidence to `min(max(c + 0.1, 0.8), 1.0)` and verifies the action. Rejection deletes it.

Runtime injects only actions from the registered project's verified instincts at confidence at least `0.8`. It does not match triggers. See [Instincts](/guides/instincts).

## Memory conflicts

```bash
orchestos memory conflicts
orchestos memory conflicts --project <name>
orchestos memory resolve <conflict-id>
```

The CLI help describes `--project <name>` as a saved name or path. The implementation passes the value directly to the stored `project_id` filter without resolving it. Use the saved project ID to filter reliably. The memory judge uses the Auxiliary role to compare a new entry with a BM25 candidate. It classifies the relation as `conflict_with`, `supersedes`, `compatible`, `scoped`, `related`, or `not_conflict`, with confidence and an explanation.

`memory conflicts` lists unresolved records. `memory resolve` marks a record resolved without changing the memory entries; it exits with status `1` if the record is missing or already resolved. Malformed judge output falls back to `not_conflict` with low confidence.

Task outcomes also write memory entries. Inspect project memory in **Settings → your project → Memory**.

## Setup, dashboard, and reset

```bash
orchestos setup
orchestos dashboard --port 4242
```

`setup` checks Bun, `node_modules`, `bun.lock` or `bun.lockb`, a signed-in AI CLI or API fallback, optional API keys, `tasks.yaml`, and `db.sqlite`. It does not check git. Run it from the installation directory when checking installation dependencies.

`dashboard` starts the local server and prints a URL with `#t=<token>`. Use that full URL on your first visit. If dependencies or the UI bundle are missing, it attempts installation or `build:app`.

`orchestos reset --yes` deletes the current registered project's runs and unverified instincts, clears associated run references, and resets that project's `tasks.yaml` state to pending with retry metadata cleared. It requires a registered project for the current directory. It preserves configuration, skills, context, and memory entries. It does not reset every project.
