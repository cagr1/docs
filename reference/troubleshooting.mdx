## A role is unassigned

A `RoleUnassignedError` uses this message pattern:

```text
Executor role is unassigned — assign it in Settings → Model routing
```

The role name changes with the failing call. Assign its agent and model in **Settings → Model routing**. Check the resolved configuration:

```bash
orchestos config show -p ./my-project
```

A project config replaces the global fallback rather than merging with it. Invalid assignments are ignored with a warning. The role loader accepts `claude`, `codex`, `opencode`, `api`, and custom global CLI IDs; it does not accept `local`.

## Dashboard returns 401 or 403

`401` with `dashboard token required` means the API token is missing or wrong. Open the full `#t=<token>` URL printed by `orchestos dashboard`. If you set `ORCHESTOS_DASHBOARD_TOKEN`, use that server's current token.

API clients send `x-orchestos-token`. Host must be `localhost:<port>` or `127.0.0.1:<port>`; Origin, when present, must match an allowed HTTP origin. Invalid Host or Origin returns `403`.

The installer opens the plain local URL. On your first visit, copy the authenticated URL from the terminal.

## The working tree is dirty

Worktree execution requires a clean tree. The task stays `pending` with an `uncommitted changes:` reason. Commit the intended changes, or use **Commit & Run** in the task card to select files before starting.

Only declare regenerable files in `sandbox.derivedFiles`: sandbox setup may discard their tracked changes. Without git or a usable base branch, `auto` can fall back to `cwd`, which has no worktree isolation.

## A task is interrupted

An interrupted card offers **Resume**. Read the last report and check project state before resuming. A failed card instead shows the cause, check output, QA reason, and executor report when available.

## Checks fail or time out

Inspect the recorded command, working directory, exit code, and output:

```bash
orchestos runs --detail <run-id>
```

The default timeout is `60000` milliseconds. Set `checks[].timeout_ms` for a check that needs more time. `cwd` must stay inside the project. Split commands into separate checks: the parser rejects shell composition tokens such as `&&` and `;`.

Check failures normally return the task to `pending` with an incremented retry count. At the third failed attempt the task becomes `failed_permanent`.

## A CLI call fails

Read the task card's failure classification and the recorded provider error.

| Failure | Action |
| --- | --- |
| Usage limit / quota | Restore credits or wait for your plan's quota window. |
| Rate limit | Wait for the provider limit to reset. Diagnosis names this pattern `rate_limit`. |
| Sign-in failed | Sign in to the selected CLI again. |
| Timed out | Inspect provider response time and the configured CLI timeout. |
| Invalid model | Choose a model available to the selected agent. |
| Network error / provider overloaded | Restore connectivity or wait for provider capacity. |
| No response / CLI exited | Read the process error and exit details before running again. |

`external.timeoutMs` defaults to `1200000` and accepts integers from `60000` to `86400000`. A detected binary alone does not prove that task execution or chat is supported for that CLI.

## Diagnose a failed task

```bash
orchestos task diagnose <task-id>
orchestos task diagnose <task-id> --model <model>
```

Diagnosis reads up to three recent runs. It uses the Auxiliary role unless you supply an OpenRouter model override. Patterns include `deterministic_check`, `qa_specific_criterion`, `parse_error`, `rate_limit`, `scope_creep`, and `unknown`. Suggestions do not edit your task.

## No pending task is executable

Check `depends_on` and task status. Dependencies must reach `done`. Parsing rejects duplicate IDs but does not reject cycles. `task run --all` stops on failure or blockage and caps execution at 20 iterations.

## A skill is missing

Check **Settings → your project → Skills**. Enable user-library skills for the project. Runtime reads YAML from the project, library, or installation; exporting with `skill build` is not an activation step.

## Spec approval fails

Approve a pending design with `spec approve-design`, resolve clarification, and supply real criteria under `## Criterios de aceptación` before `spec approve`. `spec lint` reports advisory formatting findings separately.

## Installation command is missing

Use `bun /path/to/orchestos/src/cli.ts` directly or define the shell alias in [Installation](/installation). Run `orchestos setup` from the installation directory to inspect dependencies and AI availability.
