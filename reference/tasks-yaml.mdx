Place `tasks.yaml` at your project root. You must provide a project name and a task array. Each task requires `id`, `description`, and a nonempty `output` array.

```yaml
version: 1
project: my-app
tasks:
  - id: add-health
    description: Add a health endpoint
    task_class: implement
    input: [src/server.ts]
    output: [src/routes/health.ts]
    acceptance_criteria:
      - "WHEN GET /health succeeds THEN the response contains status ok"
    checks:
      - cmd: bun run typecheck
        cwd: .
        timeout_ms: 60000
        expect_exit: 0
    depends_on: []
    status: pending
```

## Task fields

| Field | Values and behavior |
| --- | --- |
| `id` | Unique string matching `^[a-z0-9]+(-[a-z0-9]+)*$`. Lowercase letters and digits separated by single hyphens. |
| `description` | Required, nonempty task description. |
| `output` | Required, nonempty array of nonempty file paths. Defines the write contract. |
| `input` | Array of input file paths. Omitted or `null` becomes `[]`. You must list the context files you need. |
| `skill` | Primary skill ID. See [Skills](/guides/skills). |
| `executor` | `openrouter` (default), `anthropic`, `openai`, or legacy `codex`. The last requires `OS_ENABLE_EXEC_CODEX=1`. This field names a provider, not a CLI engine. |
| `executor_model` | Per-task model override. |
| `planner_model` | Optional string retained in the task schema; it does not start a planning stage. |
| `engine` | `single-shot`, `agentic`, `external` (Claude Code), `opencode`, `codex`, or `cli:<id>` for a globally configured CLI. Omit it to use configured routing. |
| `approvalMode` | `supervised`, `auto-edit`, or `full`. If absent, task execution requests `full`. Engines without action-approval support use full access. |
| `cli_effort` | Nonempty string interpreted by the selected CLI. |
| `task_class` | `plan`, `implement`, `fix`, `review`, or `doc`. Selects automatic phase skills; if absent, the harness classifies the description. |
| `acceptance_criteria` | Array of review criteria. |
| `checks` | Commands as strings or objects; see below. |
| `depends_on` | Task IDs that must reach `done` first. Defaults to `[]`. |
| `status` | `pending` (default), `running`, `done`, `failed`, `failed_permanent`, or `blocked`. |
| `retry_count` | Number of failed attempts; defaults to `0`. |
| `retry_reason` | Latest failure or waiting reason. |
| `qa_verdict` | `pass`, `fail`, or `skipped`. |
| `run_id` | Last stored run ID when recorded by the caller. |

Task rules live inside **Settings → Model routing**, in the **Task rules** row (`routing-rules`). See [Model routing](/reference/models#task-rules).

## Checks

You can write a check as a command string or as an object:

```yaml
checks:
  - bun run lint
  - cmd: bun test src/health.test.ts
    cwd: .
    timeout_ms: 60000
    expect_exit: 0
```

`cmd` is required. `cwd` defaults to the sandbox root and must stay within the project. `timeout_ms` defaults to `60000` and accepts positive integers. `expect_exit` defaults to `0` and accepts nonnegative integers.

Commands run as an executable and arguments. The parser rejects `&&`, `||`, `;`, backticks, and `$(`. Declare separate checks instead of combining shell commands. Check output retains up to 2000 characters per stream.

If you omit explicit checks, the harness can add checks for the output and available toolchain. These include TypeScript, test assertions, JavaScript syntax, Rust, and Go checks. See [Task workflow](/guides/task-workflow).

## Dependencies and state

Parsing rejects duplicate IDs. It does not reject dependency cycles. A dependency that is missing or unfinished prevents execution.

With `task run --id`, an unfinished dependency sets the task to `blocked`. With `--all`, the CLI selects a ready pending task. It stops on a failed or blocked result and exits with an error when no pending task is executable. It caps execution at 20 iterations.

A failed check or QA review normally returns the task to `pending` with `retry_count + 1`. The third failed attempt becomes `failed_permanent`. Other execution failures can set `failed` earlier. A dirty worktree leaves the task `pending` with `retry_reason`, without spending an attempt.

The reviewer runs when you declare acceptance criteria, an applicable review gate requires it, or your profile says you do not write code. Otherwise the run records `qa_verdict: skipped`.
