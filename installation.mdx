You need Bun to run OrchestOS and install its dependencies. Use git for the worktree sandbox. You also need a signed-in supported coding CLI or API credentials for the calls you configure.

## Automated installation

Clone the repository and run its installer:

```bash
git clone https://github.com/cagr1/orchestos
cd orchestos
bash install.sh
```

On macOS and Linux, `install.sh` checks Bun and attempts to install it if missing. It runs `bun install`, builds the dashboard, creates `~/.orchestos/.env` if absent, and starts the dashboard. It also tries to open `http://localhost:4242` in your browser.

<Note>
  On your first visit, use the full URL printed by the CLI, including `#t=<token>`. The installer's browser-opening step uses the plain URL without that token.
</Note>

### Windows

**Experimental — not yet tested on Windows**

From the cloned repository, run:

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1
```

You can also run `install.bat`, which launches `install.ps1`.

## Manual installation

```bash
git clone https://github.com/cagr1/orchestos
cd orchestos
bun install
bun run build:app
bun run src/cli.ts dashboard
```

Install Bun from [bun.sh](https://bun.sh) first if it is missing. Node.js does not replace Bun as the runtime. Some generated checks, such as JavaScript syntax checks, also use Node.js. Rust and Go outputs require their corresponding toolchains for applicable checks.

To call the CLI from other project directories, add an alias to your shell profile:

```bash
alias orchestos="bun /path/to/orchestos/src/cli.ts"
```

Reload your shell profile after adding it. The dashboard command attempts to build the UI if its bundle is missing.

## Connect an agent

Sign in to a supported CLI and ensure its binary is on `PATH`. Built-in task engines support Claude Code, Codex, and OpenCode. Chat capability depends on the available adapter and CLI health. On first startup, the default chat agent is the first functional installed CLI with a chat adapter; an OpenRouter key can provide an API fallback.

In **Settings → Model routing**, assign the four roles required by your workflow. A detected binary alone does not guarantee that it supports every operation. See [Model routing](/reference/models).

## Optional API keys

You need no API key for calls handled by a signed-in CLI. API execution uses its provider's key in `~/.orchestos/.env`:

```bash
OPENROUTER_API_KEY=
ANTHROPIC_API_KEY=
OPENAI_API_KEY=
```

Use `OPENAI_API_KEY` for the `openai` provider. You can also manage keys in **Settings → API keys**. See [Configuration](/configuration).

## Verify setup

From the installation directory:

```bash
orchestos setup
```

It checks Bun, installed dependencies, `bun.lock` or `bun.lockb`, AI session availability, optional keys, `tasks.yaml`, and `db.sqlite`. It does not check git. If `tasks.yaml` is absent, create it in the project where you want to run tasks:

```bash
orchestos task init ./my-project
```

Start the dashboard and open the authenticated URL it prints:

```bash
orchestos dashboard
```

Continue with [Quickstart](/quickstart), or use [Troubleshooting](/reference/troubleshooting) if setup fails.
