OrchestOS runs on Bun, uses git worktrees as its sandbox, and calls the coding CLIs installed on your machine. This page covers prerequisites, the automated installer, manual setup, and optional API keys.

## Prerequisites

- **Bun ≥ 1.1** — runtime and package manager. Install it from [bun.sh](https://bun.sh).
- **git** — required for the worktree sandbox.
- **At least one coding CLI**, logged in — `claude` (Claude Code), `codex`, or `opencode`. OrchestOS uses them with your own plan. You can skip this only if every role uses `agent: api`.

```bash
bun --version
git --version
claude --version   # or: codex --version / opencode --version
```

<Note>
  Bun is required; Node.js and Deno are not supported as runtimes. Bun and Node.js can coexist.
</Note>

## Option 1: Automated installer

The installer checks for Bun (installing it if missing), runs `bun install`, builds the dashboard UI, creates `~/.orchestos/.env`, and starts the dashboard.

<CodeGroup>
  ```bash macOS / Linux
  git clone https://github.com/cagr1/orchestos
  cd orchestos
  bash install.sh
  ```

  ```powershell Windows (PowerShell)
  git clone https://github.com/cagr1/orchestos
  cd orchestos
  powershell -ExecutionPolicy Bypass -File install.ps1
  ```
</CodeGroup>

The installer creates `~/.orchestos/.env` with an empty `OPENROUTER_API_KEY` line. Leave it empty if every role uses a CLI agent.

## Option 2: Manual install

<Steps>
  <Step title="Install Bun">
    ```bash
    curl -fsSL https://bun.sh/install | bash
    ```
  </Step>

  <Step title="Clone, install, and build the dashboard">
    ```bash
    git clone https://github.com/cagr1/orchestos
    cd orchestos
    bun install
    bun run build:app
    ```

    The dashboard is a React app built from `src/dashboard/app/` into `src/dashboard/app/dist/`. That folder is generated and not committed. `orchestos dashboard` rebuilds it automatically if it is missing.
  </Step>

  <Step title="Add the shell alias (optional)">
    ```bash
    # ~/.bashrc or ~/.zshrc
    alias orchestos="bun /path/to/orchestos/src/cli.ts"
    ```

    Reload your shell with `source ~/.zshrc` (or `~/.bashrc`).
  </Step>
</Steps>

## API keys (optional)

No API key is needed if every role uses a CLI agent. Keys are only used by roles set to `agent: api` (OpenRouter by default) and for embeddings.

```bash
mkdir -p ~/.orchestos
cat > ~/.orchestos/.env <<EOF
OPENROUTER_API_KEY=sk-or-...    # roles with agent: api (default provider)
ANTHROPIC_API_KEY=sk-ant-...    # roles with agent: api, provider: anthropic
OPENAI_API_KEY=sk-...           # embeddings (text-embedding-3-small)
EOF
```

| Key | When it is used |
|-----|-----------------|
| `OPENROUTER_API_KEY` | A role with `agent: api` and no `provider`, or `provider: openrouter` |
| `ANTHROPIC_API_KEY` | A role or task that calls Anthropic directly |
| `OPENAI_API_KEY` | Semantic re-ranking of context suggestions during `orchestos index` |

<Warning>
  `~/.orchestos/.env` holds secrets. It lives in your home directory so it stays outside every project repository. Do not commit it.
</Warning>

## Verify the installation

```bash
orchestos setup
```

`setup` reports Bun, git, the detected CLIs, and your config. Then start the dashboard:

```bash
orchestos dashboard   # http://localhost:4242
```

## Troubleshooting

**`orchestos: command not found`** — the alias is not set or your shell profile was not reloaded.

**A role fails with "sin asignar" / unassigned** — that role has no agent. Assign it in **Settings → Model routing**.

**A CLI agent is not detected** — make sure the binary is on your `PATH` and that you are logged in (run it once by itself).

**Bun installed but not detected** — open a new terminal; the installer adds `~/.bun/bin` to `PATH` for new sessions.
