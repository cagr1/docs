Skills are YAML instructions. You can assign a primary skill to a task and let automatic phase skills add relevant guidance.

## Find and create skills

```bash
orchestos skill list
orchestos skill add my-convention
orchestos skill scaffold --language TypeScript
orchestos skill languages
```

Project skills live in `skills/`. Your reusable library lives in `~/.orchestos/skills/`. Reading prefers the project, then your library, then the installation. A same-ID override shadows the installed copy.

Library skills are opt-in per project. In **Settings → your project → Skills**, enable the skills you want. OrchestOS stores activation in `.orchestos/skills.json`:

```json
{ "enabled": ["my-convention"] }
```

Use **Add skill** to import a GitHub URL pointing to a `SKILL.md` or folder into your library. Then enable it for the project.

## Define a skill

```yaml
id: my-convention
version: 1.0.0
name: My convention
description: Use the shared billing client
targets: [claude, cursor, openai]
instructions: |
  Use src/billing/stripe.ts for Stripe calls.
activation:
  mode: automatic
  phases: [implement, fix]
  triggers: [billing]
```

| Field | Meaning |
| --- | --- |
| `id`, `version`, `name` | Required identity fields. Use a kebab-case ID. |
| `description` | Required description, up to 1024 characters. |
| `instructions` | Required instruction text, up to 32000 characters. |
| `targets` | Nonempty list containing `claude`, `cursor`, or `openai`. |
| `when_to_use` | Discovery hints. |
| `activation` | `mode`: `automatic`, `suggest`, or `explicit`; optional `phases` and `triggers`. |
| `iron_law` | One required rule when supplied, up to 300 characters. |
| `common_rationalizations` | Objects with `excuse` and `refutation`. |
| `red_flags` | Warning signs to check. |
| `inputs_required` | Required context descriptions. |
| `verifiers`, `anti_patterns` | Verification commands and patterns to avoid. |
| `examples` | Objects with `title`, `input`, and `output`. |
| `language_targets` | Per-language verifiers and anti-patterns. |
| `allowed_tools` | Parsed tool-name metadata; the current shared renderer does not emit it or enforce permissions from it. |
| `source` | Import provenance: `url` and `fetchedAt`. |

## Runtime selection

The chain is `skillRoute → roadmapContext → contextInject → instinctApply`. `skillRoute` renders the primary skill plus applicable automatic phase skills. Review-only automatic skills stay in the QA path.

`task_class` chooses the phase: `plan`, `implement`, `fix`, `review`, or `doc`. Without it, the harness classifies the description. Automatic skills need a matching phase. If triggers are present, at least one must match the description case-insensitively; underscores can match spaces.

`SKILL_GUIDELINES_MAX_CHARS` is `48000`. The primary skill is included first. Additional phase skills that exceed the combined budget are omitted and recorded with a reason. The primary is not truncated by this check.

## Export and import

```bash
orchestos skill build
orchestos skill build --id my-convention --target claude --project ./my-project
orchestos skill curate "Use our shared billing client" --save
orchestos skill import <url>
orchestos skill fetch --list
orchestos skill fetch --name <id>
```

`skill build` exports to `dist/skills/<target>/`. Runtime execution loads YAML skills; it does not read those exported files. Curate, import, and fetch commands require the dashboard. Use `ORCHESTOS_API_URL` if it is on another port.
