The OrchestOS dashboard is a local web interface that gives you a visual layer on top of the same SQLite database your CLI writes to. You can inspect run evidence, track task status, approve or reject instinct proposals, and review spec lint results — all without leaving your browser. There are no external dependencies, no bundler, and no telemetry: it is vanilla JavaScript served over `localhost`.

## Starting the dashboard

```bash
orchestos dashboard
```

This starts the server at `http://localhost:4242`. Open that URL in your browser. The terminal prints the address when the server is ready:

```text
[dashboard] Server running at http://localhost:4242
```

To use a different port:

```bash
orchestos dashboard --port 3000
```

<Note>
The dashboard only binds to `127.0.0.1` — it is not exposed on your network. Mutating requests (POST, PUT, DELETE) are same-origin checked, so no other page on your machine can trigger actions against it.
</Note>

## /runs — run evidence and cost

The runs view is your primary debugging surface. Every run OrchestOS executes writes a full evidence record to SQLite: the provider and model used, input and output token counts, USD cost, the QA verdict for each acceptance criterion, files the LLM attempted to write versus files that were authorized, and any context monitor warnings.

**Cost breakdown per sub-agent** is especially useful after `--expand` runs. Each sub-task appears as a separate line in the breakdown with its own token and cost totals, so you can see which sub-agent consumed the most budget.

**Context monitor warnings** appear when the harness detects that the prompt is approaching the model's context window. Warnings here often signal that you should add explicit `input[]` to the task or run `orchestos context compress` to reduce `CONTEXT.md` from ~2000 tokens to ~500.

<Tip>
Click into any run to see the full `snapshot_before` and `snapshot_after` diff — the exact file state before the LLM wrote anything versus after QA passed. This is the same data `orchestos runs --detail <run-id>` shows in the terminal.
</Tip>

## /tasks — status board

The tasks view reads directly from `tasks.yaml` in real time. It shows every task with its current status, retry count, QA verdict from the last run, and a link to the associated run record.

From the tasks view you can:

- **Run a task** — equivalent to `orchestos task run . --id <task-id>`.
- **Explain a task** — dry-run that shows the context suggestions and prompt plan without spending tokens (equivalent to `--explain`).
- **Diagnose a failure** — for tasks at `failed_permanent`, triggers the diagnosis agent (equivalent to `orchestos task diagnose <task-id>`), which reads the last three runs and returns a structured suggestion for why the task keeps failing.

<Tip>
Keep the tasks view open in a tab while running `orchestos task run . --all` in your terminal. It refreshes automatically and gives you a real-time status board for long-running batch executions.
</Tip>

## /instincts — approve and reject proposals

The instincts view shows all instincts in your database, sorted by confidence. Auto-proposed instincts (those generated by `orchestos runs --analyze`) appear with a distinct `auto` badge and a `verified: false` indicator until you act on them.

**Approving** an instinct from the UI is identical to running `orchestos instinct approve <id>`: it bumps confidence by `+0.1` and sets `verified: true`. **Rejecting** permanently deletes the proposal.

You can also create new instincts directly from the UI — useful when you notice a pattern mid-session and want to encode it immediately without switching to the terminal.

<Note>
Changes made in the instincts UI take effect on the next run. There is no restart required — the `instinct-apply` middleware reads from SQLite on every task execution.
</Note>

## /specs — lint and approval

The specs view lists every spec file in `.orchestos/specs/`, including archived ones. Each row shows:

- **Lint badge** — `pass` if all acceptance criteria use WHEN/THEN format and delta headers are present where required; `fail` with a count of findings otherwise.
- **Free-form criterion count** — how many criteria are written as plain prose instead of structured WHEN/THEN. Free-form criteria are harder for the QA model to evaluate consistently.
- **Delta issues** — for brownfield specs that declare `modified` or `removed` capabilities, this counts missing `## ADDED / ## MODIFIED / ## REMOVED` section headers.
- **Archived specs** — specs that have been moved to `.orchestos/specs/archive/` are shown with an archived badge and excluded from the harness gate.

Use the **Approve** button to mark a spec approved and unblock task execution when `requireSpec: true` is set in `orchestos.config.yaml`.

## Using the dashboard alongside the CLI

The dashboard and the CLI share one SQLite database — there is no sync step and no separate server process to manage. You can run CLI commands and watch the dashboard update in real time.

Some workflows that work well with both open:

<Accordion title="Monitor a long --all run">
Start the dashboard, then in a separate terminal run:

```bash
orchestos task run . --all
```

Open `/tasks` in your browser. Task statuses update as each task completes, fails, or is skipped. The `/runs` view accumulates new run records as they are written.
</Accordion>

<Accordion title="Review instinct proposals after analysis">
After running:

```bash
orchestos runs --analyze
```

Switch to the dashboard's `/instincts` view to approve or reject the proposals. The inline confidence display and trigger/action text make it faster to evaluate proposals than reading the terminal table.
</Accordion>

<Accordion title="Investigate a QA failure">
When a task fails QA, the terminal shows the failed criteria. For deeper investigation, open `/runs` in the dashboard and click the failing run. The full criterion-by-criterion QA verdict, the file diff, and the cost breakdown are all visible without needing to run `orchestos runs --detail` again.
</Accordion>

<Accordion title="Check spec lint before approving">
Before running `orchestos spec approve <task-id>`, open `/specs` in the dashboard. The lint badge and free-form criterion count give you an instant view of spec quality across all tasks — useful when working on multiple features at once.
</Accordion>

## No external dependencies

The dashboard is served as static HTML, CSS, and vanilla JavaScript from the OrchestOS install directory. There is no React, no bundler, no CDN requests, and no telemetry. Everything runs locally and offline after install.
