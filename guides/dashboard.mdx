## Open your session

```bash
orchestos dashboard
```

Open the URL printed by the command, including `#t=<token>`. The default port is `4242`; use `--port` to change it. On first startup, the default chat agent is the first installed, functional CLI with a chat adapter. If none is available, OrchestOS can use the API when you have an OpenRouter key.

Add a project from the sidebar. Assign roles in **Settings → Model routing** before running tasks that need them.

## Chat and Dev

Use **Chat** to discuss your project. In **Dev**, describe the change you want. The orchestrator creates a task through `create_task` and shows a card in the conversation. You create dashboard tasks through chat.

The Dev workspace gives you:

- A file explorer and editor for project files.
- **Diff** views and a **Terminal**.
- Session tabs so you can move between conversations.
- File references: type `@` in the composer to find a project file.
- **Go to file** to open a file by name.
- Up to five attachments per message.
- A context ring that shows usage when the provider supplies it. Hover or focus it for token details.
- CLI quota indicators for functional CLIs with supported quota sources. Missing data stays unavailable.

While a response runs, use the stop control or the configured **Stop** shortcut. Messages sent during a turn can queue for that session. **Settings → Chat** lets you choose between queuing a message and stopping before sending it. You can remove a queued message before it is sent.

## Approvals

A task that touches existing files enters `held` and offers **Approve & Run** or **Reject**. With `permissionMode: manual`, new-file tasks also wait. With `yolo`, a task that only creates files can start directly.

A dirty working tree blocks worktree execution. **Commit & Run** lets you select changes to commit before starting.

The composer has a separate action-approval selector:

| Mode | Requested behavior |
| --- | --- |
| **Supervised** | Ask before edits and commands. |
| **Auto-edit** | Allow edits and ask before commands. |
| **Full access** | Run without action prompts. |

Task engines that do not support action approvals execute with full access. During a supported task, an approval request offers **Approve**, **Reject**, and **Always approve in this task**. The last choice applies to that task.

## Task evidence

A failed card shows the classified cause, the failed check and its output, the QA reason, and the executor report when available. The report is labeled as unverified. Earlier attempt reports stay folded in the card.

If execution was interrupted, the card shows **Interrupted** and offers **Resume**. Inspect the recorded state before resuming. Use the undo control on a completed card to revert a merged run.

You can inspect tasks, runs, and memory under **Settings → your project**. The project's **Graph** view currently displays `CONTEXT.md`, the branch, and clean or dirty worktree status.

## Settings

| Group | Sections |
| --- | --- |
| **App** | **General**, **Appearance**, **Keybindings**, **Terminal**, **Editor**, **Chat**, **Notifications**. |
| **Agents** | **Providers**, **Model routing**, **Executor**, **API keys**. |
| **Observe** | **Health**, **Usage**. |
| **Protect** | **Danger zone**. |

In **App → General**, choose English or Spanish and set **I write code**. The noncoding profile requires review. **Appearance** offers OrchestOS, Graphite, Carbon, and Light themes, plus interface scale. **Notifications** controls turn-finished alerts, input-needed alerts, and sound.

Inside a project's settings, **General** controls its display name, icon, base branch, and setup script. Use **Specs** for spec drafting and approval, **Skills** for the library and project activation, and **Tasks**, **Runs**, and **Memory** to inspect execution.

**Task rules** is a row inside **Model routing** (`routing-rules`). It is not a separate settings page.

## Keyboard shortcuts

Defaults use Cmd on macOS and Ctrl elsewhere for the primary modifier. Customize or reset them in **Settings → Keybindings**.

| Action | Default |
| --- | --- |
| Command palette / search settings | Cmd/Ctrl+K |
| Go to file | Cmd/Ctrl+P |
| Open settings | Cmd/Ctrl+, |
| Zoom in / out / reset | Cmd/Ctrl+=, Cmd/Ctrl+-, Cmd/Ctrl+0 |
| Switch to Chat / Dev | Alt+1 / Alt+2 |
| New chat | Alt+N |
| Toggle sidebar | Cmd/Ctrl+B |
| Toggle right panel | Cmd/Ctrl+Alt+B |
| New terminal | Ctrl+backtick |
| Close Dev tab | Alt+W |
| Next / previous Dev tab | Alt+] / Alt+[ |
| Stop a running turn | Escape |

## Local authentication

The server binds to `127.0.0.1`. It accepts **Host** values `localhost:<port>` and `127.0.0.1:<port>`. If an **Origin** header is present, it must match one of those HTTP origins.

API requests require `x-orchestos-token`. The terminal WebSocket can pass the token as `t` in its query string. The browser receives the initial token through the URL fragment printed by the CLI. A missing or wrong API token returns `401` with `dashboard token required`; an invalid Host or Origin returns `403`.

The token is stored in `~/.orchestos/dashboard-token` unless you set `ORCHESTOS_DASHBOARD_TOKEN`. See [Configuration](/configuration).
