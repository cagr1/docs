## Create the task

In the dashboard, describe a change in **Dev** chat. The orchestrator uses `create_task` to create a task and show its contract in the conversation. The project task list is an inspection view; you create dashboard tasks through chat.

For a CLI workflow:

```bash
orchestos task init ./my-project
```

Edit `tasks.yaml` with an ID, description, nonempty `output`, explicit input files, checks, and acceptance criteria. Omitted `input` is `[]`.

## Select execution

Assign roles under **Settings → Model routing**. Its **Task rules** row routes drafted tasks by output glob or skill. You can also set `engine`, `executor_model`, `cli_effort`, `approvalMode`, and `task_class` per task.

```bash
orchestos task run ./my-project --explain add-health
```

This prints task metadata, model, executor, inputs, checks, and criteria. It does not render the full prompt.

## Run and verify

Commit changes before using the worktree sandbox. In the dashboard, use **Approve & Run** for a held task or **Commit & Run** for a dirty tree.

```bash
orchestos task run ./my-project --id add-health
orchestos task run ./my-project --all
```

`--id` exits with status `1` unless the result is `done`. `--all` stops on failure or blockage and caps execution at 20 iterations.

The harness runs:

1. Spec gate, when enabled in the supplied harness config.
2. Sandbox setup, then classification and routing.
3. `skillRoute → roadmapContext → contextInject → instinctApply`.
4. Prompt build and executor call.
5. Contract validation and deterministic checks.
6. LLM review when criteria, an applicable review gate, or your noncoding profile requires it.
7. Merge or failure cleanup, with run evidence.

Checks use a default timeout of `60000` milliseconds. A failed check or QA review normally increments `retry_count` and returns the task to `pending`. At three failed attempts, it becomes `failed_permanent`. Other errors can produce `failed` earlier. A missing toolchain or dependency can produce `blocked`.

## Read failures

```bash
orchestos task status ./my-project
orchestos runs --detail <run-id>
orchestos task diagnose add-health
```

A failed task card shows the cause, failed check output, QA reason, and executor report when available. Inspect that evidence and correct the task or project before another CLI run. Interrupted tasks offer **Resume**.

Diagnosis uses the Auxiliary role unless you supply `task diagnose --model <model>`. Its suggestion does not edit the task. See [Troubleshooting](/reference/troubleshooting).
