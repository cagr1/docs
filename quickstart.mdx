## Install and open

```bash
git clone https://github.com/cagr1/orchestos
cd orchestos
bash install.sh
```

The installer checks Bun, installs dependencies, builds the UI, and starts the dashboard. Open the full URL printed in the terminal, including `#t=<token>`. The installer opens a plain browser URL, so your first visit may need that authenticated link.

For Windows, use `install.ps1` or `install.bat`: **Experimental — not yet tested on Windows**. See [Installation](/installation).

## Configure your project

Add a local project from the sidebar. Use a git repository on a branch for worktree isolation and commit your changes before starting a task.

Open **Settings → Model routing** and assign agents and models:

| Role | Purpose |
| --- | --- |
| Orchestrator | Chat and task drafts. |
| Executor | Task output. |
| Reviewer | Criteria and review gates. |
| Auxiliary | Diagnosis and memory judging. |

CLI calls use your existing sign-in session. API calls need the provider's key. The initial chat agent comes from the first functional installed CLI with chat support, or the OpenRouter API fallback.

## Ask for a change

Switch to **Dev** and describe what you want. The orchestrator creates a task through `create_task` and shows its file contract in a card.

- Use **Approve & Run** for a held task. Existing-file tasks wait for approval. `permissionMode: manual` also holds new-file tasks.
- Use **Commit & Run** when a dirty tree prevents worktree execution.
- Inspect a failed card's cause, check output, QA reason, and executor report.
- Use **Resume** for an interrupted task after checking its state.

The composer separately controls action approvals through **Supervised**, **Auto-edit**, and **Full access**. See [Dashboard](/guides/dashboard).

## Inspect the result

The harness checks the spec gate when enabled in its supplied config, sets up the sandbox, resolves classification and routing, then runs `skillRoute → roadmapContext → contextInject → instinctApply` before building the prompt.

After execution, it validates the contract and runs deterministic checks. The LLM reviewer runs when acceptance criteria, an applicable review gate, or the noncoding profile requires it. Otherwise QA is recorded as `skipped`. A successful worktree run merges its changes and records evidence.

Open **Settings → your project → Tasks**, **Runs**, or **Memory** to inspect the outcome. A failed check or QA review normally returns the task to `pending` with a higher retry count; the third failed attempt becomes `failed_permanent`.

## CLI path

Use the CLI through an alias or `bun /path/to/orchestos/src/cli.ts`. Initialize a project only when you intend to generate `AGENTS.md` and `context.json`:

```bash
orchestos init ./my-project
orchestos task init ./my-project
```

Edit the starter tasks in `tasks.yaml`. Declare a description, output files, explicit inputs, checks, and criteria. Omitted `input` becomes `[]`.

```bash
orchestos task run ./my-project --explain add-health
orchestos task run ./my-project --id add-health
orchestos task status ./my-project
orchestos runs --detail <run-id>
```

`--explain` prints task metadata, model, executor, declared inputs, checks, and criteria without calling an LLM. See [Task workflow](/guides/task-workflow).
