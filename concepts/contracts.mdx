Use `output[]` to declare the files a task may write. The list must contain at least one path.

```yaml
input:
  - src/server.ts
output:
  - src/routes/health.ts
  - src/routes/health.test.ts
```

`input[]` supplies file context. If you omit it, the parser uses `[]`. It is not a general operating-system read boundary for a CLI agent.

## API response enforcement

In API execution, the executor returns file blocks in this format:

```text
<<<FILE:src/routes/health.ts>>>
export const health = () => ({ status: 'ok' })
<<<ENDFILE>>>
```

The harness parses the response and checks paths against the output contract before writing the returned files. An unauthorized path aborts those writes and records the blocked paths.

CLI agents edit files through their own tools. Their execution path also performs contract validation and checks worktree changes. Do not treat the API file-block format as a restriction on what a CLI process can access. Use the [sandbox](/concepts/sandbox) to isolate task changes.

## Inspect the result

```bash
orchestos runs --detail <run-id>
```

The evidence includes attempted, authorized, and blocked files, snapshots, checks, and the QA verdict. A contract failure stops the attempt; read the task's `retry_reason` before running it again.

Your contract defines scope. Add deterministic checks and acceptance criteria to verify behavior. A task with `qa_verdict: skipped` did not receive LLM review.
