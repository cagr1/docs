The default sandbox mode is `auto`. In a git repository on a branch, OrchestOS uses a separate worktree for the task. Without git or a usable branch, it falls back to the current directory and warns you. A dirty git tree blocks worktree execution before the attempt starts.

## Prepare the project

Commit your changes before a worktree run. In the dashboard, **Commit & Run** lets you select the files to commit before starting the task. A dirty tree leaves the task `pending` with an `uncommitted changes:` reason.

Open **Settings → your project → General** to choose a base branch and a setup script. The setup script runs when OrchestOS creates the worktree. If you omit the base branch, it uses the current branch.

## Derived files

You can declare exact generated file paths:

```yaml
sandbox:
  derivedFiles:
    - reports/generated.json
```

Sandbox setup can discard changes to these tracked files so they do not block a run or merge. Only list files you can regenerate. The loader rejects absolute paths, parent traversal, and directory paths.

## Execution and merge

The executor and checks operate inside the task worktree. The reviewer runs when criteria, an applicable review gate, or the noncoding profile requires it. A successful run merges task changes into the base branch.

The commit merge path first attempts a fast-forward. If the base has advanced, it rebases the task branch and retries. The merge implementation also supports squash. When the base branch is not checked out in your working directory, it advances that branch without switching your checkout.

Failed worktrees are normally cleaned up. To retain one for inspection:

```bash
orchestos task run --id add-health --keep-worktree
```

`--keep-worktree` implies worktree mode. Inspect the path printed in the run log. You can inspect snapshots and file evidence with `orchestos runs --detail <run-id>`.

## Current-directory mode

```bash
orchestos task run --id add-health --sandbox cwd
```

This writes directly in your project directory and has no worktree isolation. Use it only when you intend that behavior.

## Undo a completed run

Use the undo control on the task card to revert a merged run. The card displays **Undone** and the resulting commit ID. Review the current repository state before undoing changes that later work depends on.
